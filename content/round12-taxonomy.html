Sorted · round 12 · brand kit

The six chips
don't exist.

The chip taxonomy was invented before anyone read the data model. This is the proposal to replace it with something the app actually has — and the numbers say the replacement is not a compromise but a strictly better system.

decision document pending approval governs 8 remaining screens
01

The problem

Round 2 invented a six-colour category taxonomy — food, bills, invest, transport, shopping, health — as a plausible set for a finance app. It was never checked against the codebase. It is now locked into tokens.css, tokens.ts, tokens.json, the Tailwind preset, the brand book, and both approved screens.

The app has nothing of the kind. From web/app/budgets/page.tsx and web/app/transactions/page.tsx:

type CategoryType = "expense" | "income";
type Bucket = "fixed_costs" | "investments" | "savings" | "guilt_free";

interface CategoryNode {
  _id: string; name: string;
  type: CategoryType; bucket: Bucket;
  budgetLimit: number;
  children: CategoryNode[];        // unbounded depth
}

interface Transaction {
  _id; accountId;
  categoryId: string | null;      // nullable — the parser creates these
  amount; date; note?; merchant?;
}

Categories are unbounded

A user-defined tree. Arbitrary names, arbitrary depth, created at runtime. There is no fixed set of six, or of any number. A palette cannot enumerate it.

Buckets are fixed

Exactly four, hard-coded in the type. Semantically meaningful. And guilt_free is where the dashboard's 108px hero figure comes from.

the rule at stake

“Chips never guess.” Locked and user-approved. It already forced recurring rows onto direction chips on the dashboard, because RecurringItem has no category field. Colouring an unbounded user-defined tree from a fixed palette of six breaks that same rule — on the most-used screen in the product.

02

The recommendation

Chips colour the four fixed buckets. Category name carries in text.

Colour is for the small closed set; language is for the unbounded one. That division is the whole idea. A bucket is knowable at compile time, so a chip can be assigned honestly — never guessed. A category name is a user's arbitrary string, so it belongs in text where arbitrary strings are free.

There is a second, better reason. guilt_free is not an arbitrary bucket — it is precisely where the dashboard's 108px hero figure comes from. Colouring by bucket points the entire colour system at the number the product is built around. The six invented chips pointed at nothing.

the finding that settles it

With four buckets, every chip is textSafe (≥4.5:1). The six-chip set never was — shopping at 3.32 and health at 3.46 were graphics-only, and food/health sat just 9° apart in hue, separating on lightness alone. That is what forced the “the icon is load-bearing” caveat into the brand kit.

The tightest pair in the new set is 65°. Fewer chips is not a compromise here. It is a strictly more robust system that also retires a caveat.

Rejected alternatives

AlternativeWhy not

05

Three sub-decisions

Uncategorised — categoryId: null

A hollow chip: 1.5px dashed --dim-2, no fill, question glyph. The category slot becomes an underlined Categorise action rather than a label.

This is the parser's normal output, not a failure — the Gmail ingest creates rows precisely so the owner can resolve them. Rendering it in --alert would cry wolf every morning. Dashed-and-hollow reads as an empty slot awaiting a value, which is exactly what it is, and it is the only chip in the system with no fill — so it is unmistakable at a glance down a long list.

Depth — nested categories in a flat row

The chip carries the bucket colour; the leaf name carries in text. The parent appears only when it disambiguates.

A transaction references a leaf directly, but every leaf inherits its ancestor's bucket — so the chip is always answerable no matter how deep the tree goes. Groceries › Zepto shows the parent because "Zepto" alone is ambiguous against the merchant column; Electricity stands alone because it does not need help. Never a full breadcrumb in a dense row — the row has 1fr of space and the merchant owns it.

Income rows — type: "income"

Income keeps the direction chip already locked on the dashboard: hollow with an up-arrow, ink stroke. It does not take a bucket colour.

Buckets describe where money goes. Income has no destination bucket, so colouring it would be guessing again. The dashboard already established hollow direction chips for recurring rows that lack a category; income inherits that vocabulary rather than inventing a fifth colour. One rule, applied twice.

06

Migration — every colour accounted for

Four of the six are retained and remapped. Two are retired. The system is never left in two minds.

Old tokenHexFateNew tokenNote
--bills#F1A007 retained--bucket-fixed Obligation reads as amber. Near-exact semantic carry.
--invest#23B471 retained--bucket-invest Exact semantic match. Icon survives unchanged.
--transport#5483D3 retained--bucket-savings Colour kept, meaning reassigned. New vault icon.
--food#F9ACCE retained--bucket-guiltfree The hero bucket. Highest contrast in the set at 9.80:1.
--shop#8A4BD1 retired— Was textSafe:false (3.32:1).
--health#C43C63 retired— Was textSafe:false (3.46:1).
note the symmetry

The two colours being retired are precisely the two that failed textSafe — and they were themselves added in round 3 to fix a collision the six-chip set had created. The invented taxonomy required a patch, and the patch is what we are now removing. Nothing of value is lost.

Token naming: --invest would collide with the investments bucket. All four are renamed to the --bucket-* prefix so a token name can never be mistaken for a category name again.

Icon assets: invest.svg carries over unchanged. bills.svg, transport.svg and food.svg are replaced by lock, vault and spark glyphs — the old ones describe categories, not buckets. shopping.svg and health.svg are retired with their colours. Net: four icons in the sprite, down from six.
